나쁜 소식도 BLUF입니다

“나쁜 소식은 완충재로 감싸라”는 조언은 절반만 맞습니다. 완충재는 한 겹이고, 그다음 문장에 사실이 직설로 나와야 합니다. 영어권 비즈니스에서 가장 중요한 층은 완충재가 아니라 ④ 해결책입니다.

⚠ 헤지(hedge)의 함정

may · might · possibly · a little · maybe — 한국어에서는 완곡함이지만 영어 보고에서는 정보의 삭제입니다. 확실하지 않다면 불확실성 자체를 정확히 쓰십시오. It may be delayed가 아니라 We'll know by Wednesday whether this slips; current estimate is one week.

사과의 3요소

I'm so sorry, I'm really sorry, sorry again을 다섯 번 쓰는 것은 사과가 아닙니다. 세 요소가 다 있어야 사과가 됩니다.

① 사실 인정

무엇이 언제, 누구에게 영향을 줬는지. 숫자와 시각으로.

The API returned 503s for 42 minutes, affecting all checkout traffic.
② 원인

수동태로 숨기지 마십시오. 주체가 없는 문장은 책임 회피로 읽힙니다.

We pushed a config change without a staging check.
③ 재발 방지

여기가 사과의 본체입니다. 없으면 “또 그럴 것”으로 읽힙니다.

We've added a required staging gate to the pipeline, merged this morning.

# ADR-014: Event pipeline — Kafka Status: Accepted · 2026-09-03 Context: Current queue reaches its throughput ceiling in ~6 weeks. Settlement retry requires message replay, which we lack today. Decision: We will use self-managed Kafka on EKS (3 brokers, MSK later if ops load proves too high). Alternatives: RabbitMQ — rejected: no replay Kinesis — rejected: 2.4x cost at our volume Consequences: + Replay unlocks the settlement retry work in Q4 − New system to operate; one engineer needs ramp-up time − ~$1.8k/mo added infra cost Revisit: Q1 2027, or if broker ops exceeds 4 hrs/week
